```python
class When(BaseModel):
    event: EventType
    zone: str | None = None
    camera: str = "*"
    time_range: str | None = None          # "23:00-06:00", puede cruzar medianoche
    days: list[int] | None = None          # 0=lunes .. 6=domingo
    min_confidence: float | None = None
    duration_gte: float | None = None
    person: str | None = None              # nombre o "unknown"


class Action(BaseModel):
    type: Literal["record", "snapshot", "notify", "telegram",
                  "webhook", "log", "upload_drive", "set_flag"]
    # campos opcionales especificos por tipo
    pre_secs: float | None = None
    post_secs: float | None = None
    template: str | None = None
    url_ref: str | None = None


class Rule(BaseModel):
    name: str
    enabled: bool = True
    when: When
    debounce_secs: float = 0.0
    actions: list[Action]


class RuleEngine:
    def __init__(self, rules: list[Rule], registry: ActionRegistry) -> None: ...
    async def evaluate(self, event: Event) -> list[str]: ...   # nombres de reglas disparadas
    def reload(self, rules: list[Rule]) -> None: ...
    @property
    def invalid_rules(self) -> list[tuple[str, str]]: ...      # (nombre, motivo)
```

  <action>
Crear `backend/events/rules.py` con los modelos Pydantic y el `RuleEngine`.

Puntos criticos:

1. **`time_range` que cruza medianoche**: si `start > end`, el rango es `[start, 23:59] ∪ [00:00, end]`. Es el caso mas comun (vigilancia nocturna) y el mas facil de implementar mal.

2. **Clave de debounce compuesta**: `(rule.name, event.camera_id, event.person_id or event.track_id or "")`. Un debounce global por regla haria que la alerta de una persona silenciara la de otra — es el error de diseno mas probable aqui.

3. **Validacion no fatal**: `load_rules(path)` devuelve `(rules_validas, errores)`. El arranque continua con las validas y loguea las invalidas a nivel ERROR.

4. **Purga del debounce**: el dict de ultimas activaciones se purga periodicamente; sin purga es una fuga de memoria (una entrada por track_id visto).

Escribir primero los 10 tests (RED). Usar un reloj inyectable para probar debounce y `time_range` sin depender de la hora real.
