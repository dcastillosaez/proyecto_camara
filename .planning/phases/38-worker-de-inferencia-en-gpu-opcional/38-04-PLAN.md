```python
def _report_device_fallbacks(
    pipeline: CameraPipeline,
    event_engine: EventEngine,
    recognizer: PersonRecognizer | None,
) -> None:
    """Log por motor + DEGRADED_MODE si el dispositivo efectivo no es el pedido.

    Los motores no conocen el sistema de eventos (siguen siendo adaptadores finos):
    publican device_effective/fallback_reason como atributos y quien los construye
    decide que hacer. Mismo molde que _on_recording_failure (factory.py:104-106).
    """
    engines: list[tuple[str, str, str | None]] = []
    if pipeline.detector is not None:
        engines.append(("yolo", pipeline.detector.device_effective,
                        pipeline.detector.fallback_reason))
    if pipeline.reid_engine is not None:
        engines.append(("reid", pipeline.reid_engine.device_effective,
                        pipeline.reid_engine.fallback_reason))
    if recognizer is not None:
        engines.append(("face", recognizer.face_device, recognizer.face_fallback_reason))

    for name, effective, reason in engines:
        logger.info("Motor %s en %s", name, effective)
        if not reason or name in _DEVICE_FALLBACK_REPORTED:
            continue
        _DEVICE_FALLBACK_REPORTED.add(name)
        logger.error("Fallback de dispositivo (%s): %s", name, reason)
        event_engine.degraded_mode(
            datetime.datetime.now(), reason=f"{name}: {reason}"
        )
```

   `datetime` y `logger` ya están importados en el fichero. Añadir el import de tipos que

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pipeline → `GET /api/v2/cameras/{id}/health` | datos internos que cruzan a la superficie HTTP |
| motores → bus de eventos → SQLite/WebSocket | el payload de `DEGRADED_MODE` se persiste y se difunde al dashboard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-13 | Information disclosure | `devices.*.fallback_reason` en `/health` | mitigate | El motivo se compone solo de nombres de provider, `str(model.device)` y `repr` de excepciones de torch/ORT; no incluye `camera_url`, ni credenciales, ni rutas absolutas. El endpoint ya está tras la autenticación y el rate limit `V2_RATE_LIMIT` existentes |
| T-38-14 | Denial of service | tormenta de eventos `DEGRADED_MODE` con N cámaras | mitigate | `_DEVICE_FALLBACK_REPORTED` deduplica por motor y por proceso: como máximo 3 eventos en todo el arranque |
| T-38-15 | Repudiation | fallback silencioso sin traza | mitigate | Cada fallback deja `logger.error` con el motivo real más un evento tipado persistido; prohibido `except: pass` |
| T-38-16 | Elevation of privilege | n/a | accept | Este plan no añade endpoints, ni rutas de escritura, ni cambia el modelo de autenticación |
</threat_model>
