# Phase 29 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Tailwind CDN (`cdn.tailwindcss.com`) utility classes directly in markup, no build step, no `components.json` (confirmed absent). Locked by ADR-08 / SPEC_v2 §8.2. |
| Preset | not applicable |
| Component library | none — hand-rolled components (`.card`, `.ptz-btn`, `.event-item`, `.filter-input`, `.cam-toggle`, `.intrusion-badge`) defined in `frontend/css/components.css` |
| Icon library | none — inline SVG, feather-style (24×24 viewBox, `stroke-width="2"`, `stroke-linecap="round"`, `fill="none"`), already used for every icon in `index.html` |
| Font | Inter (UI text, `font-family: 'Inter', system-ui, sans-serif`), JetBrains Mono via `.mono` class (timestamps, counters, technical/coordinate values) — both loaded from Google Fonts in `index.html` |

Phase 29 must **reuse** this system, not introduce a new one. No new dependency, framework or bundler is justified by this phase's scope (per `CLAUDE.md`).

## Spacing Scale

Declared values (must be multiples of 4) — already established across `index.html` / `components.css`, confirmed for reuse in Phase 29:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (`gap-1`/`gap-1.5`), badge internal padding |
| sm | 8px | Compact element spacing (`gap-2`, `p-2.5`) |
| md | 16px | Default card padding (`p-4`), section gaps (`gap-4`) |
| lg | 24px | not used at page level today; reserve for new "operations row" gaps if introduced |
| xl | 32px | not used; available if a full-bleed status bar needs page-edge breathing room |
| 2xl | 48px | not used at this density — this is a data-dense ops dashboard, do not introduce |
| 3xl | 64px | not used |

Exceptions:
- Icon-only touch targets (header `[⚙]` settings / `[🔔]` alerts buttons, new in Phase 29) = **44×44px minimum**, matching the existing `.ptz-btn` pattern (`width:44px; height:44px`) already defined in `components.css`. Do not shrink below this for anything clickable in the header. Both new buttons must carry an explicit `aria-label`: `[⚙]` → `aria-label="Configuración"`, `[🔔]` → `aria-label="Alertas"` — matching the existing icon-only-button convention already used throughout `index.html` (e.g. `aria-label="Parar movimiento de cámara"` on `#ptz-stop-btn`).
- Canvas overlay (OPS-05) has **zero padding/margin** — it must be pixel-aligned 1:1 over `#video-feed`, any spacing token would break the bbox-to-frame mapping.

## Typography

Reusing the scale already present in `index.html` (Tailwind utility classes), constrained for what Phase 29 introduces:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / caption | 12px (`text-xs`) | 600 semibold (`font-semibold`) | 1.5 |
| Section heading | 14px (`text-sm`) | 600 semibold (`font-semibold`) | 1.3 (`leading-tight`) |
| Metric / value | 16px (`text-base`) | 600 semibold (`font-semibold`) | 1.2 |
| Hero status / count | 30px (`text-3xl`) | 700 bold (`font-bold`) | 1.0 (`leading-none`) |

Exactly 2 weights for everything Phase 29 introduces: **600 semibold** is the default for labels, headings and metric values; **700 bold** is reserved for the one hero number per panel (matches the existing `#stat-total` pattern: `text-3xl font-bold`). Do not use 500-medium or 400-regular on any new element — those weights exist elsewhere in the pre-29 codebase (e.g. some `text-xs` captions still use `font-medium`) but are legacy, out of scope, and must not be copied into new Phase 29 markup.

Monospace (`.mono`, JetBrains Mono) is reserved for: clock, timestamps, IP/RTSP strings, pixel/coordinate readouts, FPS/latency numbers — not for prose or labels.

## Color

Dark theme, already established (confirmed via `frontend/css/base.css` and Tailwind slate palette used throughout `index.html`):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#020617` (slate-950) | Page background (`body`), video card black backdrop |
| Secondary (30%) | `#0f172a` (slate-900) with `#1e293b` (slate-800) borders | All `.card` surfaces: header, panels, list items, toggles |
| Accent (10%) | `#3b82f6` / `#2563eb` (blue-500/600) | Reserved for: header icon buttons `[⚙]` and `[🔔]` (hover/active state), focus rings (`focus-visible:outline`), any new "view detail" / "reload" text link inside the operations panels, `.ptz-btn:active` — **never** for status/severity meaning |
| Destructive | `#ef4444` (red-500) / `#dc2626` (red-600) | Destructive actions only (unchanged from existing: `#btn-reboot`, delete-events/recordings confirm buttons) — Phase 29 introduces no new destructive action |

**Status semantics are a separate, explicit traffic-light system — not the 10% accent.** This distinction matters for OPS-04/06 and success criterion 6 ("identify active alert in <3s"): status color must never be confused with "clickable/interactive" blue.

| Status | Color | Usage |
|--------|-------|-------|
| Online / OK / Confirmed | `#22c55e` / `#4ade80` (green-500/400) | Header "SISTEMA ONLINE" dot+text, WS "Activo" badge (already exists), person chip = `CONFIRMED` identity, "Sistema OK" alert row |
| Degraded / Verifying | `#f59e0b` / `#fbbf24` (amber-500/400) | Header "SISTEMA DEGRADADO" dot+text (new state), WS "Reconectando" badge (already exists), person chip = `CANDIDATE` identity, medium-severity alert row |
| Offline / Critical / Unknown | `#ef4444` / `#f87171` (red-500/400) | Header "SISTEMA OFFLINE" dot+text (new state), person chip = `UNKNOWN` / unrecognized, high-severity alert row (e.g. "Persona desconocida") |

Accent reserved for: header settings/alerts icon buttons, focus-visible outlines, inline text links ("Recargar", "Ver todas"), active/pressed control states. Never for status dots, alert severity, or the pipeline health indicator — those always use the traffic-light table above.

## Phase 29 — Layout & Component Contracts

This section is additive detail (beyond the template's fixed fields) needed by the planner/executor to implement OPS-04/05/06 without ambiguity, given the existing markup this phase must extend rather than rebuild.

### Layout (OPS-04, success criteria 1 & 6)

**Primary visual anchor: the live video panel.** It occupies the largest surface (3/5 of the grid width, full available height), is where the canvas overlay (OPS-05) renders, and is where the operator's eye lands first on load — everything else in the layout is a secondary, confirmatory read that supports the video, never competes with it for attention (no equal-weight competing hero element, no auto-playing animation elsewhere on the page).

- Target viewport: **1366×768, zero scroll**, on both the outer page and every panel's own list (existing pattern: internal `overflow-y-auto` with `max-height` on list containers, e.g. `#events-list { max-height:200px }` — keep this pattern for any new list).
- Reuse the existing `main.grid.grid-cols-1.lg:grid-cols-5.gap-4` two-column layout (video 3/5, side panels 2/5). Do not introduce a new grid system.
- The three operator questions map to fixed, always-visible zones (no accordion/collapse, no tab switching for the primary answer):
  1. *¿Está todo bien?* → header pipeline-status badge (top of viewport, sticky, already `sticky top-0 z-20`).
  2. *¿Qué ocurre ahora?* → video panel (primary anchor) with canvas overlay + "Personas ahora" panel (existing right-column top slot, replaces/extends current detection-count badge).
  3. *¿Ha pasado algo importante?* → compact "Alertas activas" panel, positioned above or beside "Personas ahora" in the right column, showing at most the top 3 active alerts by severity (full actionable timeline is out of scope — that is Phase 30 per ROADMAP OPS-07/08/09).
- Header pipeline-status badge extends the existing `#cam-status`/`#status-dot`/`#status-text` triplet from binary (online/offline) to three states (online/degraded/offline) using the traffic-light table above. Do not add a fourth state.

### Video overlay canvas (OPS-05, success criterion 4)

- New `<canvas>` element absolutely positioned over `#video-feed` (same stacking context as existing `#rec-badge`/`#res-badge`/detection badge overlays), `width`/`height` synced to the rendered `<img>` box (`clientWidth`/`clientHeight`), not the source MJPEG resolution — scale coordinates accordingly.
- Redraw driven by a **new WebSocket message type** (e.g. `type: "tracks"`) at **2 Hz** (matches success criterion 4 exactly — do not poll faster, this is a deliberate rate cap independent of MJPEG frame rate per the project's latest-frame/decoupling invariant).
- The canvas must **never** trigger a re-render or reload of `#video-feed` — it is a purely additive draw layer. `img.src` is never touched by the overlay code path (only by the existing resolution-change / retry-connection code paths).
- Per-track bounding box stroke color follows the same traffic-light table as identity state: green (`CONFIRMED`), amber (`CANDIDATE`), red (`UNKNOWN` + intrusion-flagged), 2px stroke, rounded corners not required (sharp rect, matches YOLO-style overlay convention).
- Label chip above each box: `.mono`, 11px, name or "Desconocido", background `rgba(0,0,0,0.6)` matching existing badge treatment (`bg-black/60 backdrop-blur-sm`, see existing detection badge for the exact pattern to copy).

### WebSocket reconnection visibility (OPS-06, success criterion 5)

- Reuse the existing `websocket.js` exponential-backoff reconnect (`_wsRetry` doubling 1s→30s cap) — already implemented correctly, no change needed to the retry algorithm itself.
- Reuse the existing `#ws-badge`/`#ws-label`/`#ws-icon` visual states (amber "Reconectando" / green "Activo") — already correct per the color table above.
- New requirement for Phase 29: the header pipeline-status badge (not just the WS card) must also reflect a disconnected WebSocket as part of its `degraded`/`offline` computation — a WS that has been down for >1 reconnect cycle counts toward "system not fully OK", surfaced at the top of the viewport where the operator looks first (success criterion 6, <3s recognition).

### "Personas ahora" panel (success criterion 3)

- List of currently-active identities (from `TrackRegistry`, not from historical events), each row: colored status dot (traffic-light table) + name or "Desconocido" + confirmation state label (`text-xs`, e.g. "confirmado" / "verificando" / "desconocido").
- Empty state per Copywriting Contract above.
- Count badge in the panel header, `text-3xl font-bold` hero style, matching existing `#stat-total` treatment.
