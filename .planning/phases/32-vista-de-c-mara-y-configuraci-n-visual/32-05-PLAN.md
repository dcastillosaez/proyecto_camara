`settings.js` no tiene con qué pintar ni con qué guardar.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Servidor (`label`/`hint`/mensaje 422) -> `settings-field.js` | Todo el marcado de la vista Ajustes viene del servidor; es la superficie de XSS más grande del proyecto si algún `innerHTML` interpola texto de servidor. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-15 | Tampering (stored XSS) | `settings-field.js` renderiza `label`/`hint`/`env`/mensaje 422, todos strings de servidor | mitigate | Plantillas `<template>` vacías + `textContent` exclusivamente para todo dato de servidor; ningún renderer usa `innerHTML` con interpolación (verificado por grep manual en el checkpoint de `32-08`: `grep -n "innerHTML" frontend/js/views/settings-field.js` no debe mostrar template literals con `${`) |
| T-32-16 | Tampering | `readFieldValue` envía al servidor un valor mal tipado (p. ej. string donde se espera int) | accept | El servidor (`32-02`) es la autoridad de validación (SET-03); un tipo incorrecto del cliente simplemente produce un 422 legible, no un estado inconsistente |
| T-32-17 | Information Disclosure | El popover de "Restaurar" muestra el nombre de la sección y un recuento — ambos datos no sensibles | accept | Ni sección ni recuento son secretos; no aplica mitigación |
