## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cliente HTTP -> API v2 | Body JSON no confiable que acaba cambiando que detecta el sistema |
| API -> pipeline en marcha | El endpoint muta el estado de un hilo que esta corriendo |
| API -> tabla `app_config` | Escritura persistente que condiciona todos los arranques futuros |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-27 | Tampering | cegado silencioso con `classes=[]` | mitigate | 400 explicito en el PUT con `detail` que explica la consecuencia, y `if persisted` (no `is not None`) al arrancar, para que una fila `[]` guardada por un bug no sobreviva al reinicio (Pitfall 3) |
| T-27-28 | Tampering | desactivar la clase `person` | mitigate | 400 en el backend (`LOCKED_CLASS_IDS`) por decision del usuario; el frontend ademas la muestra marcada y deshabilitada (27-10). Sin ella caerian conteo de linea, identidad, ReID y comportamiento |
| T-27-29 | Elevation of Privilege | cualquier usuario autenticado puede cambiar la deteccion | accept | No hay roles en el sistema (auth todo-o-nada, ASVS V4). Mitigacion disponible y aplicada: rate limit compartido + validacion estricta + `CONFIG_CHANGED` persistido para trazabilidad |
| T-27-30 | Denial of Service | activar muchas clases en una escena concurrida | mitigate | Lista blanca de 6 clases en el catalogo ofrecido + validacion de rango `0..79`; `AdaptiveRate` degrada solo y `/api/v2/cameras/{id}/health` lo reporta |
| T-27-31 | Denial of Service | martilleo del endpoint | mitigate | `@limiter.limit(V2_RATE_LIMIT)` (60/min) en los dos endpoints, politica unica de toda la superficie v2 (SEC-16), vigilada por `tests/test_security_regression.py` |
| T-27-32 | Repudiation | cambio de configuracion sin rastro | mitigate | `EventEngine.config_changed(...)` por cada PUT valido: queda persistido y difundido como cualquier otro evento |
