```python
class IdentityIndex:
    def __init__(self):
        self._person_ids: list[int] = []
        self._matrix: np.ndarray | None = None  # (N, 512), float32, L2-normalizado

    def add(self, person_id: int, emb: np.ndarray) -> None:
        ...  # apila en self._matrix, normaliza si no llega ya normalizado

    def search(self, emb: np.ndarray, top_k: int = 3) -> list[tuple[int, float]]:
        if self._matrix is None or len(self._person_ids) == 0:
            return []
        sims = self._matrix @ emb  # producto escalar = similitud coseno (todo normalizado)
        idx = np.argpartition(-sims, min(top_k, len(sims) - 1))[:top_k]
        idx = idx[np.argsort(-sims[idx])]
        return [(self._person_ids[i], float(sims[i])) for i in idx]

    def rebuild(self, entries: list[tuple[int, np.ndarray]]) -> None:
        ...
```
2. `np.argpartition` en vez de un `sort` completo — O(N) en vez de O(N log N), relevante para el criterio de <5ms sobre 1000 entradas repetido muchas veces.

3. El benchmark del test usa `time.perf_counter()` alrededor de cada busqueda individual (no del bucle completo) para poder calcular el percentil 95, no solo la media — una media puede ocultar un primer-llamada-lenta por alocacion de memoria.
